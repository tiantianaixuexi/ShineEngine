## 开销比率分析

**相对于直接访问的开销倍数** (x = 倍数)

| 测试项 | 开销比率 | 说明 |
|--------|----------|------|
| SmallStruct 类型查找 | **1.00x** | 与直接访问持平（缓存优化） |
| MediumStruct 类型查找 | **1.00x** | 与直接访问持平（缓存优化） |
| LargeStruct 类型查找 | **0.04x** | 比直接访问快 25 倍（静态缓存） |
| SmallStruct 字段访问 | **2.52x** | 比直接访问慢 2.52 倍 |
| MediumStruct 字段访问 | **3.01x** | 比直接访问慢 3.01 倍 |
| LargeStruct 字段访问 | **1.03x** | 与直接访问基本持平 |
| 多字段访问 (3字段) | **17.61x** | 比直接访问慢 17.61 倍 |
| 运行时/编译期哈希 | **14.27x** | 运行时哈希比编译期慢 14.27 倍 |

---

## 结论

✅ **Small struct 反射性能优秀** (<5x 开销)

- 类型查找几乎零开销（得益于静态缓存优化）
- 单字段访问开销在 1-3 倍之间，表现良好
- 编译期哈希比运行时哈希快 14 倍，验证了编译期计算的价值
